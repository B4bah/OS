### Анализ задачи "Треки и визитёры"

**Задача:**
Есть хранилище треков. Трек состоит из последовательности точек (координат). Нужно вывести длину каждого трека, используя паттерн "Посетитель" (Visitor).

**Анализ задачи**

**1. Прецеденты**

**1.1. Хранение информации о треках**
*   Хранить коллекцию треков.
*   Каждый трек хранит список точек, из которых он состоит.

**1.2. Вычисление длины трека**
*   Обойти все точки трека.
*   Вычислить расстояние между соседними точками (евклидово расстояние).
*   Просуммировать эти расстояния.
*   *Условие:* это вычисление должно быть реализовано через механизм «Посетитель».

**2. Сущности и обязанности для реализации прецедентов**

*   **UI (Пользовательский интерфейс):**
    *   Отвечает за взаимодействие с пользователем.
    *   Запрашивает у хранилища список треков.
    *   Передает каждого «посетителя» для вычисления длины.
    *   Выводит результат (длину трека) на экран.

*   **Модель (Данные и логика):**
    *   **Хранилище (`TracksContainer`):** Содержит в себе список всех треков.
    *   **Трек (`Track`):** Структура, представляющая собой последовательность точек.
        *   Обязанность: хранить список точек.
        *   Обязанность: уметь принимать "Посетителя" (метод `Accept`).
    *   **Точка (`Point`):** Структура, представляющая координату.
    *   **Посетитель (`IVisitor`):** Интерфейс, который объявляет метод `Visit` для каждого типа элемента, который он может посещать (в нашем случае только `Track`).
    *   **Конкретный посетитель (`LengthCalculatorVisitor`):** Реализация интерфейса посетителя.
        *   Обязанность: содержать логику вычисления длины трека при его "посещении".
        *   Обязанность: хранить и предоставлять результат вычисления.
